# RUN — กลับรายการขายซ้ำของงานสิ้นวัน (TASK-750 · REQ-130)

> **สำหรับเจ้าของระบบ (รันเอง)** — สคริปต์นี้แก้บัญชีจริง วิศวกร/SA **ไม่เคยรัน** กับฐานข้อมูลใด ๆ
> ใช้ครั้งเดียวต่อเครื่อง (sid → uat) หลังนำโค้ดแก้ "ขายซ้ำ" (`d33e249` + TASK-749) ขึ้นเครื่องนั้นแล้ว

## มันแก้อะไร
งานสิ้นวัน (end-of-day) ที่ถูกรันซ้ำของวันเดิม เคยบันทึกยอดขาย trial / 1 ชม. / อื่นๆ ที่ตั้งราคา **ซ้ำ** เป็น `rev:<id>#n`
(ยอดซ้ำโผล่ใน P&L / Revenue by activity / Customer spend)

สคริปต์นี้ **เพิ่มแถวกลับรายการ** ให้ยอดซ้ำเหล่านั้น — เหลือ **1 รายการขายที่ยังมีผล** ต่อการจอง (รุ่นสูงสุด)
ด้วยเหตุนี้การกด Undo การเข้าเรียนครั้งถัดไปยังทำงานถูกต้อง และงานสิ้นวันรอบถัดไปจะไม่บันทึกซ้ำอีก

## สิ่งที่มัน **ไม่** ทำ
- ไม่แก้และไม่ลบแถวบัญชีเดิม (เพิ่มแถวกลับรายการเท่านั้น — แบบเดียวกับ Undo การเข้าเรียน)
- ไม่แตะการจอง / การเข้าเรียน / โควตา / ข้อความ LINE
- หน้าจอแสดงเฉพาะรหัสการจอง จำนวนเงิน และชื่อฐานข้อมูล/โฮสต์ที่เชื่อมอยู่ — ไม่แสดงชื่อลูกค้า, user, รหัสผ่าน หรือ URL

## รันที่ไหน
รันที่ **เครื่อง local ของเจ้าของ** ในโฟลเดอร์ `smart-scheduler-back` ที่ checkout ไว้ (branch `dong` ที่ commit `5382fe4` ขึ้นไป)
**ไม่ใช่บน server** — server มีแต่โค้ดที่ build เป็น dist แล้ว รันสคริปต์นี้ไม่ได้

เลือกปลายทางด้วยไฟล์ env ของเครื่องนั้น:

| ปลายทาง | คำสั่ง (ลองรันก่อน) |
|---|---|
| **sid** | `bun --env-file=.env.sid run sale:reverse-duplicates` |
| **uat** | `bun --env-file=.env.uat run sale:reverse-duplicates` |

> ⚠️ ไฟล์ `.env` ปกติอาจชี้ไปที่ฐานข้อมูลไหนก็ได้ — ใส่ `--env-file` ทุกครั้ง และอ่านบรรทัด `เป้าหมาย:` ก่อนเสมอ

## ขั้นตอน (ทำทีละกล่อง: sid ก่อน แล้ว uat)

**0) หาตัวเลขที่ควรได้ จากกล่องนั้นเอง ก่อนรัน** — รัน SQL 1 และ SQL 2 (คิวรีเดิมที่ใช้ตรวจยอดซ้ำ) บนกล่องนั้น
ตัวเลขที่คาดไม่ได้มาจากเอกสารนี้ — มาจากกล่องนั้นตอนนั้น (เพราะอาจมีรอบ end-of-day รันซ้ำเพิ่มหลังจากเคยนับ)

**1) ลองรัน (DRY RUN — ไม่เขียนอะไร):** คำสั่งในตารางข้างบน
บรรทัดแรกที่แสดงคือ **เป้าหมาย**:
```
เป้าหมาย: <ชื่อฐานข้อมูล> @ <โฮสต์>
```
แล้วตามด้วยรายการ `รหัสการจอง · วันที่ · ประเภท · รุ่นที่กลับรายการ · จำนวนเงิน` และสรุปจำนวนการจอง + ยอดรวม จากนั้น **rollback ทั้งหมด**

**2) ตรวจก่อน `--commit` ทุกครั้ง:**
- **บรรทัด "เป้าหมาย" ต้องเป็นฐานข้อมูลของกล่องที่ตั้งใจ** (sid = sid, uat = uat) — ถ้าไม่ใช่ **หยุดทันที ห้าม `--commit`**
- **ยอดรวมของ DRY RUN ต้องเท่ากับยอดรวมของ SQL 2 ของกล่องนั้น** (และจำนวนการจองตรงกับ SQL 1) — ถ้าไม่ตรง **หยุด** แล้วแจ้งทีม

**3) เขียนจริง** (เพิ่ม `-- --commit` ต่อท้ายคำสั่งเดิม):

| ปลายทาง | คำสั่ง |
|---|---|
| **sid** | `bun --env-file=.env.sid run sale:reverse-duplicates -- --commit` |
| **uat** | `bun --env-file=.env.uat run sale:reverse-duplicates -- --commit` |

**4) รันซ้ำเพื่อยืนยัน:** `--commit` ครั้งที่สองต้องแสดง **0 รายการ** (รันซ้ำได้อย่างปลอดภัย)

## ตรวจหลังรัน
รัน **SQL 1** อีกครั้งบนกล่องนั้น — ต้องคืน **0 แถว**
และยอดรวมใน P&L / Revenue by activity ของวันที่เกี่ยวข้องลดลงเท่ากับยอดรวมที่ DRY RUN แสดง

## ถ้าเกิดข้อผิดพลาด
สคริปต์ทำงานใน transaction เดียว — ถ้าไม่สำเร็จจะ **ไม่มีการเปลี่ยนแปลง (rollback)** และแสดงข้อความ `✗ … ไม่สำเร็จ` ให้แจ้งทีมพร้อมข้อความนั้น
