# RUN — กลับรายการขายซ้ำของงานสิ้นวัน (TASK-750 · REQ-130)

> **สำหรับเจ้าของระบบ (รันเอง)** — สคริปต์นี้แก้บัญชีจริง วิศวกร/SA **ไม่เคยรัน** กับฐานข้อมูลใด ๆ
> ใช้ครั้งเดียวต่อเครื่อง (sid → uat) หลังนำโค้ดแก้ "ขายซ้ำ" (`d33e249` + TASK-749) ขึ้นเครื่องนั้นแล้ว

## มันแก้อะไร
งานสิ้นวัน (end-of-day) ที่ถูกรันซ้ำของวันเดิม เคยบันทึกยอดขาย trial / 1 ชม. / อื่นๆ ที่ตั้งราคา **ซ้ำ** เป็น `rev:<id>#n`
(uat: รันซ้ำของ 18 ต.ค. ทำให้ 13 การจองถูกบันทึกขายซ้ำ ≈ 17,751.00 บาท — โผล่ใน P&L / Revenue by activity / Customer spend)

สคริปต์นี้ **เพิ่มแถวกลับรายการ** ให้ยอดซ้ำเหล่านั้น — เหลือ **1 รายการขายที่ยังมีผล** ต่อการจอง (รุ่นสูงสุด)
ด้วยเหตุนี้การกด Undo การเข้าเรียนครั้งถัดไปยังทำงานถูกต้อง และงานสิ้นวันรอบถัดไปจะไม่บันทึกซ้ำอีก

## สิ่งที่มัน **ไม่** ทำ
- ไม่แก้และไม่ลบแถวบัญชีเดิม (เพิ่มแถวกลับรายการเท่านั้น — แบบเดียวกับ Undo การเข้าเรียน)
- ไม่แตะการจอง / การเข้าเรียน / โควตา / ข้อความ LINE
- หน้าจอแสดงเฉพาะรหัสการจองกับจำนวนเงิน ไม่แสดงชื่อ

## ที่ไหน / อย่างไร
รันบน **เครื่องนั้นเอง** ในโฟลเดอร์ของ back (`smart-scheduler-back`) โดยใช้ค่า env ของเครื่องนั้น (ไม่ต้องใส่ค่าลับในคำสั่ง)

**1) ลองรันก่อน (DRY RUN — ไม่เขียนอะไร):**
```
bun run sale:reverse-duplicates
```
จะแสดงรายการ: `รหัสการจอง · วันที่ · ประเภท · รุ่นที่กลับรายการ · จำนวนเงิน` แล้วสรุปจำนวนการจองกับยอดรวม จากนั้น **rollback ทั้งหมด**

**ตรวจรายการให้ตรงกับที่คาดก่อน** แล้วค่อยไปข้อ 2:
- **uat:** 13 การจองของวันที่ 2026-10-18 (9 FIRST_TRIAL + 4 SINGLE_SESSION) ยอดรวม ≈ **17,751.00 บาท**
- **sid:** ของ Tanya 4 การจอง ยอดรวม **4,470.00 บาท**

ถ้ารายการ **ไม่ตรง** (มีวันอื่น / จำนวนอื่น) — **หยุด อย่ารัน `--commit`** แล้วแจ้งทีม

**2) เขียนจริง:**
```
bun run sale:reverse-duplicates -- --commit
```
**3) รันซ้ำเพื่อยืนยัน:** คำสั่ง `--commit` ครั้งที่สองต้องแสดง **0 รายการ** (รันซ้ำได้อย่างปลอดภัย)

## ตรวจหลังรัน
ใช้ **SQL 1** ตัวเดิมที่ใช้ตรวจยอดซ้ำ (คิวรีที่หา "การจองที่มียอดขายซ้ำ") — ต้องคืน **0 แถว**
และยอดรวมใน P&L / Revenue by activity ของวันนั้นลดลงเท่ากับยอดรวมที่ DRY RUN แสดง

## ถ้าเกิดข้อผิดพลาด
สคริปต์ทำงานใน transaction เดียว — ถ้าไม่สำเร็จจะ **ไม่มีการเปลี่ยนแปลง (rollback)** และแสดงข้อความ `✗ … ไม่สำเร็จ` ให้แจ้งทีมพร้อมข้อความนั้น
